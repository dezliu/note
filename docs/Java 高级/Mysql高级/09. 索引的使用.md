# 索引的使用

## 1. 验证索引提升查询效率

索引是数据库优化最常用也是最重要的手段之一, 通过索引通常可以帮助用户解决大多数的MySQL的性能优化问题。

在表 tb_item 中， 一共存储了 300 万记录；
 A. 根据ID查询

```
select * from tb_item where id = 1999\G;

```

![1553261992653.png](09. 索引的使用_assets/1553261992653.png)

查询速度很快， 接近0s ， 主要的原因是因为id为主键， 有索引；
 ![attachment-13.png](09. 索引的使用_assets/attachment-13.png)

B. 根据 title 进行精确查询

```
select * from tb_item where title = 'iphoneX 移动3G 32G941'\G;

```

![1553262215900.png](09. 索引的使用_assets/1553262215900.png)

查看SQL语句的执行计划 ：
 ![1553262469785.png](09. 索引的使用_assets/1553262469785.png)

处理方案 ， 针对title字段， 创建索引 ：

```
create index idx_item_title on tb_item(title);

```

![1553263229523.png](09. 索引的使用_assets/1553263229523.png)

索引创建完成之后，再次进行查询 ：
 ![1553263302706.png](09. 索引的使用_assets/1553263302706.png)

通过explain ， 查看执行计划，执行SQL时使用了刚才创建的索引
 ![1553263355262.png](09. 索引的使用_assets/1553263355262.png)

### 2.2. 避免索引失效

#### 2.2.1. 全值匹配 ，对索引中所有列都指定具体值。

该情况下，索引生效，执行效率高。

```
explain select * from tb_seller where name='小米科技' and status='1' and address='北京市';

```

![attachment-6.png](09. 索引的使用_assets/attachment-6.png)

#### 2.2.2. 最左前缀法则

如果索引了多列，要遵守最左前缀法则。指的是查询从索引的最左前列开始，并且不跳过索引中的列。
 匹配最左前缀法则，走索引：
 ![attachment-21.png](09. 索引的使用_assets/attachment-21.png)

违法最左前缀法则 ， 索引失效：
 ![attachment-14.png](09. 索引的使用_assets/attachment-14.png)

如果符合最左法则，但是出现跳跃某一列，只有最左列索引生效：
 ![attachment-5.png](09. 索引的使用_assets/attachment-5.png)

#### 2.2.3. 范围查询右边的列，不能使用索引 。

![attachment-4.png](09. 索引的使用_assets/attachment-4.png)
 根据前面的两个字段name ， status 查询是走索引的， 但是最后一个条件address 没有用到索引。

#### 2.2.4. 不要在索引列上进行运算操作， 索引将失效。

![attachment-18.png](09. 索引的使用_assets/attachment-18.png)

#### 2.2.5. 字符串不加单引号，造成索引失效。

![attachment-1.png](09. 索引的使用_assets/attachment-1.png)
 由于，在查询是，没有对字符串加单引号，MySQL的查询优化器，会自动的进行类型转换，造成索引失效。

#### 2.2.6. 尽量使用覆盖索引，避免select *

尽量使用覆盖索引（只访问索引的查询（索引列完全包含查询列）），减少select * 。
 ![attachment-10.png](09. 索引的使用_assets/attachment-10.png)
 如果查询列，超出索引列，也会降低性能。
 ![attachment-23.png](09. 索引的使用_assets/attachment-23.png)
 **Tips:**
 using index ：使用覆盖索引的时候就会出现
 using where：在查找使用索引的情况下，需要回表去查询所需的数据
 using index condition：查找使用了索引，但是需要回表查询数据
 using index ; using where：查找使用了索引，但是需要的数据都在索引列中能找到，所以不需要回表查询数据

#### 2.2.7. 用or分割开的条件

如果or前的条件中的列有索引，而后面的列中没有索引，那么涉及的索引都不会被用到。示例，name字段是索引列 ， 而createtime不是索引列，中间是or进行连接是不走索引的 ：

```
explain select * from tb_seller where name='黑马程序员' or createtime = '2088-01-01 12:00:00';

```

![attachment-12.png](09. 索引的使用_assets/attachment-12.png)

#### 2.2.8. 以%开头的Like模糊查询，索引失效

如果仅仅是尾部模糊匹配，索引不会失效。如果是头部模糊匹配，索引失效。
 ![attachment-9.png](09. 索引的使用_assets/attachment-9.png)
 **解决方案 ：** 通过覆盖索引来解决
 ![attachment-19.png](09. 索引的使用_assets/attachment-19.png)
