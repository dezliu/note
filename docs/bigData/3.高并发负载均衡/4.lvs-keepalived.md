#### keepalived

- keepalived是集群管理中保证集群高可用的服务软件

- 高可用 High Available

- 1、需要心跳机制探测后端RS是否提供服务

  - a) 探测down，需要从lvs中删除该RS

  - b) 探测发送从down到up，需要从lvs中再次添加RS.

- 2、Lvs DR, 需要主备 (HA)

##### keepalived 原理：

VRRP协议(虚拟路由冗余协议) - Virtual Router Redundancy Protocol
 IP漂移

##### keepalived 安装：

- 可以不用安装 ipvsadm -lnc

- keepalived (ipsadm, 自身高可用)

- yum install keepalived

- service keepalived start 启动

- /etc/keepalived/keepalived.conf

- tail /var/log/message 查看日志

```
ipvsadm -C                    #内核的配置清掉
ifconfig eth0:3 down        #网卡配置down掉
# 无论ip地址还是内核模块的配置，未来都是由keepalived启动的时候由keepalived读取配置文件自己去设置，不用人工设置了。

```

####### keepalived.conf

- global_defs：全局配置，设置邮箱，如果由谁挂了的话，会发邮件

- vrrp_instance VI_1: 虚拟路由冗余协议相关配置

  - state MASTER或BACKUP（配置MASSTER的主机若挂掉修复后会抢回主服务器，一般主服务器较贵，备服务器便宜），配置node0001为MASTER，node0004为BACKUP

  - interface 网卡接口，服务器一般配置多个网卡

  - virtual_router_id: 配置虚拟id

  - priority: 100 优先级，要唯一，master要给的最大

  - authentication 验证

  - virtual_ipaddress VIP的配置

- virtual_server: LVS相关配置

  - lb_algo rr 轮询模式

  - lb_kind DR 模式

  - net_mask 掩码

  - persistence_timeout 持久化时间，秒为单位，因为是实验环境，要保证轮询，因此设置为0

  - protocol TCP tcp协议

  - real_server 192.168.231.32 80

    - weight: 权重

    - SSL_GET: 健康检查的配置(https), 还有HTTP_GET，但是用的webserver是http的因此改为HTTP_GET

      - url 设置路径和判断条件

    - connect_timeout 连接超时时间

    - nb_get_retry 失败重试次数

    - delay_before_retry 失败重试间隔

###### node0001 & node0004

```
man 5 keepalived.conf
# 可以查看keepalived.conf 的配置帮助

vim keepalived.conf
#编辑vrrp_instance VI_i -> virtual_ipaddress
virtual_ipaddress {
    192.168.231.100/24 dev eth0 label eth0:7
    # 等价于keepalived会代替人工配置 ifconfig eth0:7 192.168.231.100/24
}

virtual_server 192.168.231.100 80 {
    lb_kind DR      # 轮询
    real_server 192.168.231.32 80 {
        weight 1
        HTTP_GET {
            url {
                path /
                status_code 200
            }
        }
    }
    real_server 192.168.231.33 80 {
        weight 1
        HTTP_GET {
            url {
                path /
                status_code 200
            }
        }
    }
}
# 后面的virtual_server不需要了，直接删掉, 复制realServer,粘贴
:wq

scp ./keepalived.conf root@192.168.231.34:/etc/keepalived/
# 或scp ./keepalived.conf root@192.168.231.34:`pwd`

# node0004
cd /etc/keepalived
vim keepalived.conf
vrrp_instance.. {
    state BACKUP
    priority 50
}
:wq

service keepalived start
ifconfig
ipvsadm -ln
# node0004的VIP不会配置，如果配置会重复出现，只要主服务器或者就不配置
# ipvsadm -ln 内核模块会配置，没有影响，没有vip数据包过不来

# 用另一台电脑
curl http://192.168.231.100:80
# 访问多次
ipvsadm -lnc
# 只有主服务器有

```

##### 如果keepalived挂掉

###### node0001

```
ps -ef | grep keepalived
kill -9 ...
# keepalived 有多个进程
# 一个主进程（MASTER）的广播自己的存活状态
# 其他为MASTER进程生出的子进程，去访问real server 做健康检查
# 这个时候 keepalived的进程被意外杀死，没有来的及释放内存，ifconfig的配置和ipvsadm都还在，而备服务器也配置了ifconfig，这样客户端访问，可能会访问到不同的负载服务器，客户端三次握手的包被打散到两个server上，结果谁也不给客户端开辟资源，连接建立不了。
```
