1. 过滤器执行流程

  1. 执行过滤器

  1. 执行放行后的资源

  1. 回来执行过滤器放行代码下边的代码

1. 过滤器生命周期方法

  1. init：在服务器启动后，会创建Filter对象，然后调用init 方法。只执行一次，用于加载资源

  1. doFilter：每一次请求被拦截资源时，会执行，执行多次

  1. destory：服务器关闭后，Filter 对象被销毁。如果服务器是正常关闭的，会执行destory 方法。只执行一次，用于释放资源

1. 过滤器配置详情

  -
拦截路径配置：

    1. 具体资源路径：/index.jsp 只有访问index.jsp 资源时，过滤器才会被执行

    1. 拦截目录：/usr/* 访问 /user 下的所有资源时，过滤器都会被执行

    1. 后缀名拦截：*.jsp 访问所有后缀名为 jsp 资源时，过滤器都会被执行

    1. 拦截所有资源：/* 访问所有资源时，过滤器都会被执行

  -
拦截方式配置：资源被访问的方式

    - 注解配置：

      - 设置 dispatcherTypes 属性

        1. REQUEST：默认值。浏览器直接请求资源

        1. FORWARD：转发访问资源

        1. INCLUDE：包含访问资源

        1. ERROR：错误跳转资源

        1. ASYNC：异步访问资源

```
// 浏览器直接请求index.jsp资源时，该过滤器会被执行(浏览器访问localhost:端口/index.jsp，过滤器会执行，访问 /AServlet，转发到index.jsp 过滤器不会执行)

@WebFilter(value="/index.jsp", dispatcherTypes= {DispatcherType.FORWARD， DispatcherType.REQUEST})

    // ...
}
```

1. 过滤器链（配置多个过滤器）

  - 执行顺序：如果有两个过滤器：过滤器1和过滤器2

    1. 过滤器2

    1. 资源执行

    1. 过滤器1

  - 过滤器先后顺序问题：

    1. 注解配置：按照类名的字符串比较规则比较，值小的先执行

      - 如：AFilter 和 BFilter，AFilter 就先执行了

    1. web.xml 配置：`<filter-mapping>`谁定义在上面，谁先执行

**eg:**

```
import javax.servlet.Filter

 @WebFilter("/*")                   // 访问所有资源之前，都会执行该过滤器
public class FilterDemo implements Filter {
    // 在服务器启动后，会创建Filter对象，然后调用init 方法。只执行一次，用于加载资源
    public void init(FilterConfig filterConfig) throws ServletException {
        System.out.println("init...");
    }

    // 每一次请求被拦截资源时，会执行，执行多次
    public void doFilter(ServletRequest servletRequest, ServletResponse servletResponsem FilterChain filterChain) {
        System.out.println("doFilter...");
        filterChain.doFilter(servletRequest, servletResponse);
    }

    // 服务器关闭后，Filter 对象被销毁。如果服务器是正常关闭的，会执行destory 方法。只执行一次，用于释放资源
    public void destory() {
        System.out.println("Destory...");
    }
}

```
